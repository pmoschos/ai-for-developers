Παρατηρήσεις για το Βήμα 4: Πείραμα Prompt Engineering

1. Σύγκριση prompt quality

Όταν το prompt είναι ασαφές, όπως "a sort function", το μοντέλο έχει μεγάλο περιθώριο ερμηνείας και μπορεί να επιστρέψει μια γενική λύση χωρίς ξεκάθαρες επιλογές για αλγόριθμο, τύπους δεδομένων ή ειδικές απαιτήσεις.

Όταν το prompt είναι συγκεκριμένο, όπως "a function that implements quicksort with in-place partitioning for a list of integers", το αποτέλεσμα είναι πιο στοχευμένο και πιο κοντά σε αυτό που ζητάμε. Το μοντέλο έχει λιγότερη αβεβαιότητα και είναι πιο πιθανό να παράγει σωστό docstring, κατάλληλα type hints και πιο σαφή λογική.

Συμπέρασμα:
Όσο πιο σαφές και συγκεκριμένο είναι το prompt, τόσο καλύτερη και πιο προβλέψιμη είναι η ποιότητα του παραγόμενου κώδικα.

2. Πείραμα με temperature

Με temperature=0.2 η έξοδος είναι πιο σταθερή και συνήθως ακολουθεί πιο πιστά τις οδηγίες του prompt. Αυτό είναι σημαντικό στην παραγωγή κώδικα, όπου θέλουμε ακρίβεια και συνέπεια.

Με temperature=0.9 η έξοδος γίνεται πιο "δημιουργική", αλλά και πιο απρόβλεπτη. Σε τέτοιες τιμές μπορεί να εμφανιστούν διαφορετικές προσεγγίσεις, πιο "ελεύθερη" διατύπωση ή ακόμη και λιγότερο αξιόπιστες υλοποιήσεις.

Συμπέρασμα:
Για code generation προτιμάμε χαμηλό temperature, επειδή μειώνει την τυχαιότητα και αυξάνει την πιθανότητα να παραχθεί σωστός και σταθερός κώδικας.

Γενικό τελικό συμπέρασμα

Το prompt engineering παίζει καθοριστικό ρόλο στην ποιότητα της εξόδου. Η σαφήνεια στο prompt και η σωστή επιλογή temperature βοηθούν το μοντέλο να παράγει πιο αξιόπιστο, χρήσιμο και ελεγχόμενο κώδικα.
